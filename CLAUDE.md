# Panicakes — прототип для гейм-джема

2D-игра на ~15 минут: кухня на Луне, низкая гравитация. Предметы хватаются мышью и подбрасываются
(быстрый рывок + отпускание = бросок по инерции). По бокам стенки, внизу плита/кастрюля/блендер/нож
(нож режет предметы в воздухе). Периодически дует ветер. Если подбросить слишком высоко — продукт
поджаривается солнечной радиацией.

## Движок

- Godot 4.7.2 standard (не .NET) → только GDScript. Бинарник: `/Applications/Godot.app/Contents/MacOS/Godot`.
- Рендерер `gl_compatibility` — чтобы потом без проблем собрать web-билд для itch.io.
- Базовое разрешение 1280×720, stretch `canvas_items` / `expand`.
- Окно: `window/size/mode=4` (exclusive fullscreen) — только в экспортах. `mode.editor=0`: бинарник редактора
  (Play в редакторе, все `tools/*`) всегда в окне — `--windowed` сам по себе фулскрин проекта НЕ отменяет.
  `mode.web=0`: в браузере фулскрин включает `scripts/app.gd` по отпусканию ЛКМ (нужен жест пользователя).
  Esc — выход на десктопе (`_unhandled_key_input`). Настоящий фулскрин проверять так (займёт экран ~5 с):
  `/Applications/Godot.app/Contents/MacOS/Godot --path . -- --window-mode=4 --stats=60 --quit=300 --shots=240`.
  На этом Mac: окно 3456×2168 (под вырезом камеры), видно 1280×802, oversampling 2.703, 120 fps.
- `physics/common/physics_interpolation=true` (плавность на 120/144 Гц при 60 тиках). Правила: всё, что двигает
  узлы, — в физическом тике (tween'ы `set_process_mode(Tween.TWEEN_PROCESS_PHYSICS)`); после спавна, телепорта
  или правки transform вне тика — `reset_physics_interpolation()` (Item._ready и эффекты удара уже делают).
  Статичная `Camera` — `physics_interpolation_mode = OFF` (иначе после ресайза канвас на тик отстаёт).
  Цена: удерживаемый предмет рисуется примерно на тик позже курсора.
- Export templates на ноутбуке пока не установлены (нужны только для финальной сборки).
- Справочник API именно этой версии (только сигнатуры и дефолты, без описаний):
  `tools/godot-api/extension_api.json` и `tools/godot-api/doc/classes/<Class>.xml`
  (там же дефолты ProjectSettings). Имена методов/свойств сверять с ним, а не с памятью.

## Цикл работы

```bash
tools/check.sh                                  # импорт + парсинг всех .gd + 10 кадров headless; exit 1 при ERROR/WARNING
tools/run.sh 420 --input=$PWD/dev/inputs/throw_up.json --probe=1 | python3 tools/probe_summary.py
                                                # headless (без окна), fixed 60 fps; сводка: апогей, GRAB/RELEASE
tools/run.sh 180 --shots=30,90                  # с --shots (или WINDOW=1) — окно --windowed 1280×720; скриншоты в tools/shots/fNNNNN.png
tools/run.sh 200 --resize=1280x800@5,2560x720@60 --shots=50,90   # смена размера окна на кадре — все пропорции за один запуск
WINDOW=1 REALTIME=1 tools/run.sh 600 --stats=60  # реальное время (без --fixed-fps) — только так видна плавность/интерполяция
tools/record.sh 240 throw --input=...           # tools/movies/throw.mp4 + throw-sheet.png (раскадровка)
SCENE=res://scenes/other.tscn tools/run.sh 60   # запустить конкретную сцену
tools/svg_sheet.sh $PWD/tools/shots/x.png 0.5 assets/sprites/a.svg ...   # растеризация SVG движком Godot, headless
```

Аргументы после `--` разбирает автолоад `dev/harness.gd` (без них он ничего не делает):
`--quit=N`, `--probe=N` (печать `PROBE f=… pos vel` для узлов группы `probe` каждые N кадров;
если у узла есть `probe_state()` — его словарь дописывается в строку), `--shots=a,b,c`, `--input=file.json`,
`--resize=WxH@F,...`, `--stats=N` (режим/размер окна, видимая область, oversampling, fps, доля интерполяции),
`--window-mode=N`. Headless-окно харнесс выставляет 1280×720 (иначе 64×64 и видимая область 1280×1280).

Формат `--input` (координаты — мировые, с учётом камеры; кадры — физические тики):
```json
[{"f": 5, "t": "move", "x": 640, "y": 600}, {"f": 6, "t": "down"},
 {"f": 7, "t": "drag", "x": 700, "y": 300, "frames": 5}, {"f": 12, "t": "up"}]
```
`drag` — линейное движение от текущей точки за `frames` кадров. Событие, вброшенное на кадре N,
скрипты получают на кадре N. Вброшенные события: `device=4242`, `window_id=INVALID` (не склеиваются с реальными
при накоплении). В любом прогоне с аргументами реальная клавиатура глушится (Esc пользователя не закроет прогон),
при `--input` — и реальная мышь. С интерполяцией и `--fixed-fps 60` доля интерполяции всегда 0: кадр скриншота
или видео N показывает тела в состоянии `PROBE f=N-1` (HUD, маркеры, частицы — тик N).

Окно Godot на macOS всегда забирает фокус при старте (`activateIgnoringOtherApps` в `show_window`,
флагами не отключается; `open -g`, `no_focus`, `lsappinfo`, `--embedded` проверены — не помогают).
Поэтому всё, что можно проверить числами, гонять headless; окно — только для скриншотов/видео, редко и пачкой.

## Механика (что уже есть)

- `scenes/main.tscn` + `scripts/main.gd`: колонна 800 px между стенками (x 240…1040, стенки до y −9300),
  пол y=680, сверху открыто. `Camera` (Camera2D) в центре (640, 360): при stretch `expand` лишнее место на
  экранах не 16:9 делится поровну. Визуал с запасом: борты на 1200 px наружу, столешница во всю ширину,
  под ней `Cabinet` (плитка до y 1720), фон с небом от y −480 — на 16:10/4:3/21:9/32:9 пустот нет.
  Отладочная строка и маркеры привязаны к видимому верху экрана (`get_canvas_transform`). `gravity` (px/s², сейчас 350) применяется к пространству через
  `PhysicsServer2D.area_set_param` — меняется на лету. Вверху отладочная строка (g, скорость броска, апогей)
  и маркеры `▲высота` для предметов выше экрана. Воздуха нет: `default_linear_damp=0`.
- `scenes/item.tscn` + `scripts/item.gd` (`class_name Item`, RigidBody2D, слой 2, CCD); конкретные продукты —
  наследники в `scenes/items/` (radius, color для маркера, texture, impact_effect). Пока держат —
  гравитация 0, скорость тянется к цели (`follow_strength`), движение в неподвижный мир (`world_mask`)
  срезается: контакт (`get_rest_info`, до 2 поверхностей) + `cast_motion` → скольжение вдоль стенки/пола.
- Удары: в `_integrate_forces` новый контакт (по collider_id) с |Δv| ≥ `impact_threshold` (140) → в
  `_physics_process` сплющивание `Squash` по нормали (elastic tween) + `impact_effect.play(normal, power)`.
  Эффекты `scenes/fx/{juice,flakes,dust}.tscn` (`scripts/impact_effect.gd`, CPUParticles2D; узлы с
  `metadata/strong_only` — только при power ≥ 0.45). `probe_state()` отдаёт hits/hit_at/hit_n/hit_v.
- `scripts/grabber.gd`: захват `intersect_point` по слою 2, бросок = средняя скорость курсора за
  `history_window` (0.1 с) × `throw_scale` (0.6), не больше `max_throw_speed` (1200). Сигнал `thrown`.
- Сценарии в `dev/inputs/`: `throw_up` (ожидание: v=−1200, подъём ≈ v²/2g ≈ 2050 px, ~3.4 с),
  `gentle_drop` (v=0), `side_throw` (отскок от правой стенки), `into_wall` (держится на x≈271),
  `along_floor` (y=648, в углу x≤1008), `showcase` (три броска с ударами всех типов; удары на кадрах
  51/111/209/271). После правок физики прогонять их все.

## Арт

SVG, рисуются кодом. Стиль: пастель, мягкие формы, контур — более тёмный оттенок заливки (не чёрный),
заливка radialGradient со светом сверху-слева, белый полупрозрачный блик-эллипс, мультяшное лицо
(тёмные глаза с белым бликом, розовый румянец, маленькая улыбка). Без SVG-фильтров.
- Всё в `assets/sprites/` импортируется как **DPITexture** (в `.import`: `importer="svg"`, `type="DPITexture"`,
  `fix_alpha_border=true`; в редакторе Import As → DPITexture) — перерастрируется под масштаб экрана.
  Новый SVG по умолчанию получит обычный импорт и будет мыльным в фулскрине — `check.sh` это ловит.
  Частицы `assets/fx/` — обычные текстуры (CPUParticles2D не масштабирует DPITexture).
  У тайловых спрайтов `region_filter_clip_enabled = true`, иначе на краях шов от повтора текстуры.
- Продукты `assets/sprites/<name>.svg`: холст 176×176, тело радиусом 60 по центру (88,88);
  в игре `Sprite.scale = radius / texture_body_radius(60)`.
- Тайлы рисуются в 2× (`width/height` = 2× `viewBox`), в сцене `scale = 0.5`, `region_enabled` +
  `texture_repeat = 2`: `wood_wall.svg` (борт с планкой справа; правый борт — `flip_h`), `countertop.svg`.
- Фон `background.svg` 1280×1200 (y −480…720, генерируется `python3 tools/gen_background.py <out.svg>`;
  z −10), борты/пол/`cabinet.svg` z −1 (шкафчик до y 2720). Цвет очистки = верх неба #232550, так что на
  экранах выше 4:3 сверху нет шва. Портретная раскладка не задумана (дыр нет, но поле мелкое).

## Известные мелочи

- Web: при живом ресайзе окна браузера каждый новый масштаб перерастрирует все DPITexture (~40 мс при ×2.7).
- Маркеры ▲ рисуются по позиции тика, спрайты — по интерполированной: на 120 Гц маркер чуть дрожит.
- Тачпад vs мышь: бросок считается по последним 0.1 с до отпускания — ощущение на трекпаде не проверено. Частицы `assets/fx/` 32–64 px.
- Палитра: лук #EDC6E5/#AC77A3, помидор #FFA095/#D0666B, картошка #F0CE9F/#BA8C5E, листья #AADE9C/#70A967,
  дерево #EBCCA5/#C1925F, плитка #C2E6D4/#9ED0B9, небо #2F3262→#9483B6, глаза #4B3A4F, румянец #F59DBB.

## Соглашения по коду

- GDScript с типами, отступы табами, без комментариев.
- Позицию мыши брать **только из InputEvent** (`event.position` → `make_input_local`/canvas transform),
  не из `get_global_mouse_position()`: она читает реальный курсор ОС и игнорирует события харнесса.
- Скорость броска считать по своей истории позиций за последние кадры, а не по `event.velocity`
  (у реальной мыши он шумный).
- Настройки ощущений (гравитация, сила броска, ветер, пороги радиации) — `@export`-переменные,
  чтобы крутить в инспекторе.
- Визуал — `Polygon2D`/`Sprite2D`. Если нужен `Control` поверх игрового поля — `mouse_filter = IGNORE`,
  иначе он съест клики.
- `.tscn` пишутся руками без `uid` — Godot допишет при сохранении в редакторе. Если редактор открыт —
  после правок на диске он предложит перезагрузить сцену; несохранённые правки в редакторе затрут мои.
- `tools/` закрыт `.gdignore` — ассеты игры туда не класть.
